API documentation

HTTP endpoints on http://127.0.0.1:8000 (loopback by default)

Overview

capps manages local apps defined in apps.json. Most actions poll health for up to 60 seconds and return success or failure. Failover groups (e.g. cursor-agent-telegram) use primary/backup logic on start, stop, restart, and status.

Prefer the unified status and control endpoints for automation (Home Assistant, scripts). Per-app routes remain for the dashboard and backward compatibility.

Status

MethodPathDescription
GET /api/apps/status Refresh all dashboard apps. Returns {"apps": [...], "results": [...]}.
GET /api/apps/status?app_id={id} Refresh one app (failover-aware). Same response shape with one entry each.
GET /api/apps Same as /api/apps/status (all apps).
GET /api/apps/{app_id} Refresh one app; returns a single result object (not wrapped in apps/results).
GET /api/apps/catalog App metadata only — no health probes (used for initial dashboard layout). 
curl http://127.0.0.1:8000/api/apps/status
curl "http://127.0.0.1:8000/api/apps/status?app_id=gauth"

Control

MethodPathDescription
POST /api/apps/control JSON body: {"app_id": "...", "action": "start"|"stop"|"restart"}. Same behavior as the per-app routes below.
POST /api/apps/{app_id}/start Start app if stopped.
POST /api/apps/{app_id}/stop Stop a running app.
POST /api/apps/{app_id}/restart Stop then start (via each app’s shutdown API where configured).
POST /api/apps/{app_id}/start-debug Start with debug launcher when configured (not available for all apps).
POST /api/apps/start-all Start every autostart dashboard app that is not running.
POST /api/apps/stop-all Stop every manageable dashboard app that is running. 
curl -X POST http://127.0.0.1:8000/api/apps/control \
  -H "Content-Type: application/json" \
  -d "{\"app_id\": \"gauth\", \"action\": \"restart\"}"

Action responses include success, message, elapsed_seconds, and an app object with current status fields.

Failover watchdog

When failover_groups is set in apps.json, capps polls primary health on an interval (default 1 hour) and can fail over to a backup after consecutive failures. Disable with CAPPS_WATCHDOG=0.

MethodPathDescription
GET /api/failover/schedule List watchdog schedule state and any temporary overrides.
POST /api/failover/schedule Temporary faster polling. Loopback only. JSON: exactly one interval field (interval_sec or every_minutes) and one duration field (duration_sec, for_hours, or for_minutes). Optional group_id.
DELETE /api/failover/schedule Clear override(s). Loopback only. Optional query ?group_id=.... 
curl -X POST http://127.0.0.1:8000/api/failover/schedule \
  -H "Content-Type: application/json" \
  -d "{\"every_minutes\": 5, \"for_hours\": 2}"

Local shutdown

MethodPathDescription
POST /api/local/shutdown Exit the capps server process (dashboard “Stop server”). Loopback only. Returns {"ok": true, "shutting_down": true} before exit.

App IDs

Use ids from apps.json (e.g. gauth, notetaker, voice-dictation, cursor-agent-telegram). Backup failover entries are hidden from the dashboard but may be referenced by id; API calls typically resolve to the primary failover app.
